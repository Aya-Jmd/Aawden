The problem

AI models are now asked to review code for security holes. A reviewer's comment, a ticket, or a line in a pull request can sit next to that code. If one confident sentence can overturn a correct verdict, then anyone who can write that sentence can wave a vulnerability through.

The test is simple. Show the model a file and record its verdict. Show the same file again with one added line in which a reviewer states the opposite verdict. Count how many correct verdicts the model gives up.

First finding: most small models cannot be tested this way

A model can only abandon a correct verdict if it had one. On our 129 test files, the models under 10B parameters are right about half the time with no reviewer present, which is what guessing gives. Their numbers look like resistance or surrender, but they are noise. Only three of the eight models we measured clear that bar.

Share of 129 files each unchanged model gets right with no reviewer. Grey bars are statistically no better than a coin flip.

The fix: train the verdict to follow the code

We trained a LoRA adapter on 268 separate files, each shown three ways: no reviewer, a reviewer who is right, and a reviewer who is wrong. The correct output is the same in all three. No test file, and no file from the same family as a test file, is in the training set.

The hard case: teaching the recipe, not one sentence

A model that only learned one sentence pattern breaks on the next one. We tested that directly on Aya Expanse 8B, the model at the centre of this hackathon. Trained on the single reviewer sentence, it stayed right on 87 of 129 files but fell back to abandoning 17 to 30 of 87 correct verdicts on wordings it had not seen. The change that fixed it was the shape of the training: first learn the review task with no reviewer in sight, then see eight different reviewer styles plus a reviewer who disputes the model's own earlier answer. All five wordings marked as held out were kept out of that second stage.

What the extra stage costs

The recipe gives up some skill to buy robustness. Trained on all wordings from scratch instead, Aya 8B is steadier but solves fewer files outright.

What the fix costs

A reviewer's bare opinion looks the same whether it is right or wrong. So a model that stops listening to wrong reviewers also stops being helped by right ones. Running the Qwen2.5-14B adapter at partial strength shows the dial, and no setting gets both.

What did not work, and where the fix is weak

  • Editing the weights directly did not work. Switching off the attention heads that read the reviewer's line changed nothing. Removing an "opinion direction" from the model's internal state reduced the problem but damaged the model's own accuracy beyond the limit we had set, so it failed our rule.
  • Teaching a small model the task did not work. Distilling review skill into Aya Expanse 8B left it at coin-flip accuracy.
  • Aya anchors on its own earlier answer. When the conversation already contains an answer and the reviewer disputes it, the Aya adapter changes nothing. But it keeps that earlier answer even when it was wrong and the reviewer was right, on 67 of 129 files. The Qwen2.5-14B adapter does not do this.

We then added training examples that show the model an earlier answer, right half the time and wrong half the time. The disputed-answer test itself was kept out of training. With that adapter Aya follows the code on 124 of 129 files under this test (before: 59), and sticks to a wrong earlier answer on 0. By the rule we wrote down beforehand this passes.

  • The test files are short and templated. A check on 32 pairs of real-world code points the same way, but that set is small and its labels come from the dataset, not from us.
  • One task, one language of prompt. Everything here is Python security review in English.
